## Platform

web

## Users

- **主用户**：需要记录每日出差路径与里程的业务人员（跑客户、送货、跑厂区），典型场景是在**车间、厂区、客户楼下用手机单手记一笔**，之后回到办公室用桌面浏览器补齐或核对。
- **同一产品下的其他用户**：使用者的同事，各自独立账号、**数据相互隔离**（彼此不共享、不互相查看）。**实测现状（2026-10-10）**：线上只有使用者的 1 个账号（4 条行程、232 公里、4 个活跃会话），其他用户尚未加入——多人能力是「已具备、待发生」，因此多用户相关界面目前没有第二份真实数据可验证。
- **管理员**（角色，由 `ADMIN_USERNAMES` 环境变量按用户名指定，当前为 `zerobiubiu`）：只做账号运维——看用户列表（行程数 / 合计里程 / 最近活跃）、重置密码、启用/禁用、删除用户。
- **已确认方向（尚未实现）**：管理员可查看**任一用户的行程明细**（列表与导出）；需要新增接口与页面，属于后续 shape 的输入。（2026-10-10 复核：保留）
- **明确否认的假设**：普通用户之间没有「看别人数据」的角色，也不做团队/部门维度的汇总。

## Product Purpose

把原本写在文本里的行程账（日期 + 节点链 + 里程）搬进随手可填的应用：打开就是今天、节点按历史补全、分段里程默认带出历史值、总里程由分段合计得出，月末不再手算。
成功的样子：**一次行程 30 秒内录完，且历史数据随时可汇总、可导出**。

## Positioning

用「**节点链 + 历史路线记忆**」而不是「起点 → 终点」记里程：常跑的路线（家 → 圣润 → 天九 → 圣润 → 家）第一次手填之后，后续点一下就能带出全部分段与总里程；**同一条路的往返里程相同**，只需一侧有数据，反向也能自动带出，不必两边各记一次。

## Operating Context

- 记录发生在路上：厂区、车间、客户现场；一只手操作，屏幕在户外光线下看。
- 补录与核对发生在桌面浏览器：看月度汇总、导入历史文本、导出备份。
- 账号运维发生在任何浏览器：管理员通过标题栏「账号 → 管理」处理他人密码、启停与删除，不必再手连数据库。
- 历史存量是**纯文本**，写法由用户形成习惯：`9.28`、`家，依剑，爱克森，圣祥小镇，圣润 57 公里`、`单次25km`、`7.1-7.2` 区间、`203 公里` 小计、`------` 分隔线。产品必须能解析这种写法并导入（含预览与去重）。
- 术语沿用用户自己的语言：节点、分段里程、总里程、行程、常用路线、导入。

## Capabilities and Constraints

已实现：

- **账号**：开放注册（已确认保留；需要收紧时可设置 `SIGNUP_CODE` 邀请码，无需改代码）、登录（长期登录态、多设备独立、滚动续期）、改密、退出、多设备会话列表与逐个登出、改显示名。
- **填报（0.10.0 起节点与分段一体编辑）**：日期默认今天；**路线编辑区是一条连续的路线**——每个节点一行（可就地改名、可拖手柄排序），行下方紧接「到下一站的里程」，从上到下读就是 `家 → 25 → 圣润 → 12 → 天九`；**节点名默认先选后输**（点一下先给常用节点候选列表，**不弹软键盘**；点右侧键盘图标才进入手动输入，输入时模糊匹配 + 按使用频率排序）；**每一段里程必填**（默认带出历史值，可改；未填齐不允许保存）；**总里程 = 分段合计**；备注可选；同一天可多条行程。
- **智能带出**：分段里程同方向历史优先，没有同方向时按**反方向**推断（同一条路往返同值，界面不区分方向）；**节点候选按使用频率排序**（口径：该节点名出现在多少条已保存行程里，次数相同按最近使用；来源是既有的 `buildIndex(trips)`，不新增存储）；整条历史链可一键填入；输入中的草稿本地持久化，刷新、断网或 401 之后都能恢复。
- **查询中心（汇总，0.8.0）**：时间范围（本月 / 本年 / 去年 / 全部 / 自定义起止）+ 读数带（总里程 / 行程次数 / 出行天数 / 单次均值）+ 四种聚合维度（**按月份 / 按路线 / 按分段 / 按节点**，各带排序与前 10 项展开）+ 点某一行带着该行的条件跳到记录页看明细；缺里程时给一条点击即筛的可操作提示。分段维度**不分方向**（`家 ⇄ 圣润` 合成一条），与「同一条路往返里程相同」一致。
- **记录（明细查询，0.8.0）**：同一时间范围控件 + 关键词（节点名或备注）+ 只看未填里程 + 排序（最新在前 / 里程从高到低，后者为降序榜单并带日期头）+ 结果摘要（条数 / 合计里程 / 缺里程条数）+ 条件胶囊可逐个移除 + 无匹配时一键清空条件；按月/日分组浏览，每 60 条分页。
- **导出**：JSON 导出。
- **导入**：历史文本解析 + 预览 + 按 `日期+节点链` 去重（导入的记录允许只有总里程，不强制分段）。
- **管理**：用户列表、重置密码、启用/禁用（禁用即刻使其全部会话失效）、删除（级联清理行程与会话）。

技术与运营约束：

- 运行时：Cloudflare Workers（Hono）+ D1 + KV；前端 React SPA 作为静态资源由同一个 Worker 的 `assets` 绑定托管，API 与前端**同 Worker、同域名**，一次 `wrangler deploy` 发布。
- 前端组件库：**MUI（Material UI）v9**（含 emotion 样式引擎与 @mui/icons-material），日期统一用 `@mui/x-date-pickers`（dayjs 适配器 + 中文文案）；拖动排序用 dnd-kit（MIT）。设计系统见 `apps/web/DESIGN.md`。
- **自定义时间范围用两个只读日期字段（起始 / 截止），不用 Range Picker**：免费包 `@mui/x-date-pickers` 里没有 range 组件（9.15.0 实测无任何 `*Range*` 导出），`DateRangePicker` 属于 **Pro 包**（`@mui/x-date-pickers-pro`，商业许可）。两个字段同时与「日期只选不敲、值在框内居中、等宽数字」的既有字段语言一致，不引入第二套日期交互。
- **浏览器支持基线（2026-10-08 修订，用户明确选择）**：Chrome ≥117 / Edge ≥121 / Firefox ≥121 / Safari ≥17（macOS 与 iOS）。微信内置浏览器**仅在系统内核满足该基线时**在支持范围内；旧机型与旧微信内核不在支持范围。
- **连续曲率是增强，不改基线**：圆角语言由形状令牌（半径档位 + 嵌套规则）承载，所有浏览器一致；超椭圆曲线（`corner-shape: squircle`）只在支持的浏览器（Chrome / Edge 139+，MDN BCD 实测；Safari 与 Firefox 目前仅预览版）上生效，不支持的浏览器继续画圆弧，布局与状态不受影响。
- 密码：PBKDF2-SHA256，迭代受 workerd 10 万次上限约束；**无邮箱找回**——忘记密码由管理员在应用内重置（管理页），必要时仍可在 D1 侧处理。
- 安全：CSP 严格但放行 `style-src 'unsafe-inline'`（MUI/emotion 运行时注入样式，静态托管无法按请求下发 nonce）；`script-src` 仍不允许内联。
- 体积：**首屏闭包约 831 kB**（入口 chunk 649 kB + 静态共享块 174 kB + 运行时 8 kB，含 React + MUI + 日期控件；0.11.0 实测）；记录/汇总/导入/账号/管理视图按需懒加载。只看「入口 chunk」会误判——打包器会让共享模块在入口与共享块之间重新归并（0.8.0 那次入口涨 53 kB，净增其实只有 4.6 kB）。这个值随功能增长：0.8.0 记录 748 kB，**0.11.0 实测 831 kB**（差额来自 0.9–0.10 的路线编辑、行程卡与拖动依赖；0.11.0 的多形态适配只增加 252 字节）。
- 计时口径：日期取用户本地时区（不存时区）；里程以公里为唯一单位，保留两位小数，上限 100000 公里。

**方向（已确认、尚未实现）**：产品要从「里程记录」扩展为「**出差台账**」——记录费用、客户、备注并汇总。范围、字段与汇总口径尚未确定，属于后续 shape 的输入，不要在实现里自行发明。（2026-10-10 复核：保留）

## Product Principles

1. **录一笔要快**：默认今天、历史补全、一键沿用；节点与路线由用户的语言决定。
2. **每一段都要有数**：分段必填、总里程由分段合计得出——账要经得起核对，宁可多按几次键盘，也不要出现对不上的总数。
3. **用用户的语言**：节点名、路线、历史写法都由用户决定（可中文、可沿用原有文本格式）。
4. **路上录、桌面核**：路上用手机单手完成录入；汇总、导入、导出这类重操作留给桌面。
5. **数据是用户的**：可导出、可导入、不做锁定；不引入第三方跟踪。

## Accessibility & Inclusion

用户确认的使用条件（**硬约束**，后续设计必须照顾）：

- **手机为主**（iOS Safari / Android Chrome），桌面偶尔使用；
- **支持基线**：Chrome ≥117 / Edge ≥121 / Firefox ≥121 / Safari ≥17（macOS 与 iOS）；微信内置浏览器需系统内核满足该基线，旧机型不在支持范围；
- **需要大字与高对比**：户外光线、年龄偏大的使用者；字号一律用 rem（`html` 基准），界面上可见文字不低于 14px；
- **需要单手可操作**：加节点、填里程、保存这三个关键动作必须在拇指可达区，触摸目标 ≥44px。
