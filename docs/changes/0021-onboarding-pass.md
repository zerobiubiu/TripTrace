- **状态**：已执行
- **版本**：0.11.4
- **日期**：2026-10-10

- **影响范围**：`apps/web/src/views/AuthScreen.tsx`、`views/RecordsView.tsx`、`views/StatsView.tsx`、`views/EntryView.tsx`、`App.tsx`；设计台账 `apps/web/DESIGN.md`
- **前置文档**：[0020-performance-pass.md](0020-performance-pass.md)

## 背景与已确认前提

`onboard` 的规则是「把用户尽快送到**证明这个产品值得花时间**的那一刻」，而不是教完所有功能。用户在本轮明确三件事：

1. **aha 时刻** = **录完第一笔就看到自动补全与当日合计**（因此空态的出路指向「填报」，而不是导入）；
2. **新用户偏生手**，可以更直白——但硬约束不变（户外、单手、年龄偏大、可见文字 ≥14px、不堆解释）；
3. **允许**在「从未有数据」的空态里放一个可点的出路（需要同步改 DESIGN.md 的「空态只写现状」）。

**取证（零数据首次进入实测）**：填报页已有引导且不卡（无历史时点节点名**直接进输入态**，实测「无候选（无历史节点）」，没有死路）；但**记录页与汇总页的空态没有任何控件**（「去「填报」添加第一条吧」只是文字）；**登录屏只有品牌与表单，没有一句价值说明**——同事第一次拿到链接时不知道这是什么。

## 实施

| # | 改动 | 说明 |
| --- | --- | --- |
| 1 | 登录屏加两行价值说明（`AuthScreen.tsx`） | 「记出差路线与里程：打开就是今天。」/「常跑的路线下次一键带出，月末不用手算。」14px `text.secondary`、动词开头、不写实现细节 |
| 2 | 记录页「从未有数据」空态给出路（`RecordsView.tsx` + `App.tsx`） | 文案收成一句现状「还没有行程记录。」+ **一个**按钮「去填报」（`onCreate` → `setTab("entry")`）。与「被条件筛空」那条分支（只写现状 + 清空条件）明确分开 |
| 3 | 汇总页同上（`StatsView.tsx` + `App.tsx`） | 同一套：`trips.length === 0` 时给按钮；「这一范围还没有记录」仍只在被筛空时出现 |
| 4 | 填报页提示**按历史切换**（`EntryView.tsx`） | 还没有任何行程时，节点候选**必定是空的**，文案不再承诺「可以从常用里选」，改说「点节点名直接打字（不会弹键盘）」；有历史才恢复原话。这是文案在说一件界面上不存在的事，属纠正而非美化 |
| 5 | 台账同步（`DESIGN.md`） | 空态一节分成「从未有数据 / 被条件筛空」两种；新增「登录屏（首次进入）」一节（价值说明 + **明确不做引导流程/遮罩层/已看过标记**）；路线编辑区补「提示按历史切换」 |

**刻意没有做的**：引导流程、遮罩式 tour、进度步骤、「已看过」标记、单独的教程模式。这个产品只有四个分组，参考里的「Make It Optional」「Context Over Ceremony」指向同一条路：**引导落在空态与按情境切换的文案里**，而不是一个要跳过的东西。

## 已知限制

- **未做真机验证**：户外反光、单手操作下的首次进入体验仍需真机复核（沿用前几轮的遗留项）。
- **没有分析埋点**：无法统计完成率 / 跳过率 / time-to-value，只能用自动化路径代替真实用户数据；onboard 参考里的「Time to value」指标目前只有定性判断（零数据到第一笔：添加节点 → 打字 → 填里程 → 保存，无死路）。
- 空态出路只指向「填报」（按用户选定的 aha）。**导入**这条更快的存量入口没有出现在空态里——刻意只给一条出路；若将来真实用户更多是「先导入旧账」，应改指向导入。
- 未做多语言：文案只有简体中文。

## 后续验证建议
