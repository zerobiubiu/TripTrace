# 0014 记录页的总公里数改为「读数」写法（0.9.2）

- 状态：已执行
- 影响范围：`apps/web/src/views/RecordsView.tsx`（行程卡的里程、当日合计）、`apps/web/DESIGN.md`（一条命名规则）
- 前置文档：[0013-shape-language.md](0013-shape-language.md)
- 生效版本：0.9.2
- 不涉及：数据逻辑、整体布局、其他组件（用户在 4 处只有一处被改，见「范围」）

## 背景

用户以 `/impeccable quieter` 指出：历史记录里总公里数的**胶囊形视觉样式突兀**，要求移除，让它融入现有设计语言、与列表里其他辅助信息协调；保留数值可读性与必要的层级；不改数据逻辑、整体布局与其他组件。

取证（改造前）：`RecordsView` 的行程卡把总里程渲染成 `Chip size="small" color="primary"`（蓝色实心胶囊），缺里程时换成琥珀实心胶囊；当日合计也是 `Chip`。问题不只是「圆」——按设计系统自己的规则，**蓝色只表示「可操作 / 已选中」（The One Voice Rule）**，一个纯读数用蓝色实心胶囊既抢注意力又违反了这条规则；缺里程是状态，但用实心琥珀也偏响。

## 方案

把它改回这个项目本来就在用的**读数**写法（汇总页的行读数、读数带都是这样）：

- 总里程：`Typography variant="body1"` + `fontWeight 650` + 等宽数字，颜色用墨色（`text.primary`）；**不再用蓝色**。
- 缺里程：同一处改用琥珀**文字**「未填里程」（状态色只表达状态，The State-Only Rule），不再套实心胶囊。
- 当日合计：由 `Chip` 改为 `body2` + `text.secondary` + 等宽数字 + `ml: auto`，与**月度合计的写法完全一致**（列表里两级合计因此在同一套语言里）。
- 行程卡上仍保留「导入」标记胶囊：它是标记（tag）不是读数，胶囊本来就是标记的语言。
- 把这条规则写进 DESIGN.md（**The Reading-Not-Pill Rule**），避免以后又在读数上套胶囊。

**范围**：只改「记录」页。填报页的「当日记录」列表里有同样的里程胶囊，但那是另一个视图/场景（该区块已有当日合计说明），本轮按「不要借机进行无关的 UI 重设计」未改动；是否一起改由用户决定（见后续验证建议）。
